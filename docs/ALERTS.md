# ALERTS — 微信 AI 使用技巧整理站

> Stage 12 交付物。告警规则与响应。

## 1. 告警分级

| 级别 | 定义 | 响应时间 | 渠道 |
|---|---|---|---|
| P0 | 站点完全不可用 / 数据丢失风险 | 5 分钟 | 短信 + 微信 |
| P1 | 核心功能故障 / 错误率 > 5% | 30 分钟 | 微信 |
| P2 | 性能退化 / 单功能异常 | 4 小时 | 邮件 |
| P3 | 信息 / 预警 | 工作时间内 | 日报 |

## 2. 告警规则

### 2.1 P0 规则

#### ALERT-P0-001：站点 5xx > 10% 持续 1 分钟
- **来源**：CloudBase 函数日志
- **触发**：5xx 错误率（按分钟计）> 10% 持续 60 秒
- **响应**：见 RUNBOOK §F-1

#### ALERT-P0-002：数据库连接失败
- **来源**：所有函数
- **触发**：连续 3 次 `pg.connect` 失败
- **响应**：
  1. 检查 CloudBase PG 实例状态（是否暂停）
  2. 手动唤醒
  3. 看 PG 是否 OOM

#### ALERT-P0-003：备份连续 2 次失败
- **来源**：backup-weekly cron
- **触发**：连续两个周日 03:00 备份失败
- **响应**：
  1. 检查 cron 配置
  2. 手动触发备份测试
  3. 检查存储桶权限

### 2.2 P1 规则

#### ALERT-P1-001：核心 API 5xx > 5% 持续 5 分钟
- **来源**：CloudBase 函数日志
- **触发**：API 路由 5xx > 5% 持续 5 分钟

#### ALERT-P1-002：搜索 P95 > 1s
- **来源**：API 网关日志
- **触发**：过去 5 分钟 P95 > 1000ms

#### ALERT-P1-003：MCP 调用失败率 > 10%
- **来源**：mcp-server 函数日志
- **触发**：过去 5 分钟 JSON-RPC error 占比 > 10%

#### ALERT-P1-004：证书 / 域名异常
- **来源**：外部证书监控
- **触发**：TLS 证书 < 7 天到期 / 域名解析失败

### 2.3 P2 规则

#### ALERT-P2-001：用量 > 80%
- **来源**：CloudBase 控制台
- **触发**：月资源点 > 2400 / 3000

#### ALERT-P2-002：单日费用 > ¥10
- **来源**：CloudBase 账单
- **触发**：当日按量付费费用 > ¥10

#### ALERT-P2-003：CDN 回源流量 > 50% 配额
- **来源**：CloudBase 控制台
- **触发**：CDN 回源 > 5GB（月配额 10GB）

#### ALERT-P2-004：数据库容量 > 80%
- **来源**：CloudBase 控制台
- **触发**：DB 存储 > 800MB（假设 1GB 上限）

### 2.4 P3 规则

#### ALERT-P3-001：新版本依赖
- **来源**：Dependabot
- **触发**：每周一汇总

#### ALERT-P3-002：备份大小异常
- **来源**：backup 函数
- **触发**：备份大小与上周相比 ± 50%

## 3. 告警降噪

- 同类告警 5 分钟内只发一次
- 已知维护窗口内静默
- 已 ack 的告警 30 分钟内不重复

## 4. 告警通道

### 4.1 配置

CloudBase 监控 → 告警策略：
- 邮件：`your-email@example.com`
- 微信：扫码绑定（详见 CloudBase 文档）
- 短信：仅 P0 启用（按条计费）

### 4.2 自托管补充

Uptime Kuma（可选）：
- 主页 / API / MCP 三个 endpoint 的 HTTP 探活
- 1 分钟间隔
- 失败 2 次触发

## 6. 值班与升级

- 值班：作者本人
- 升级：无（单人项目）
- 兜底：故障超 4 小时无响应，临时将首页改为「维护中」页面（CloudBase 控制台 → 静态托管 → 替换首页）

## 7. 告警复盘

每个 P0/P1 事故：
- 24 小时内写 INCIDENT-XXX
- 1 周内改进告警或测试
- 季度审视误报率
